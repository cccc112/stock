## 1. 一句話現況

**程式碼與資料庫已就緒並通過測試，但線上網站目前還不能用**：後端新版本尚未推送部署，且前端（Vercel）還沒指向新的後端網址。照第 3 節的步驟做完，約 15 分鐘可上線。

### 系統架構（目前）

```
瀏覽器 ──► Vercel（Next.js 前端）
              │  NEXT_PUBLIC_API_URL
              ▼
          Render（FastAPI 後端，新加坡，免費方案）
```

## 2. 這一輪完成了什麼

**資料正確性**
- 統一報價層：台股 TWSE → Yahoo → FinMind，美股 Yahoo → yfinance；自動判斷上市/上櫃；回傳資料來源與是否過期；全部失敗時退回上次成功的資料而非 404。
- 修正：收盤後用昨收當現價、上櫃股 404、休市日 Yahoo「假日線」使漲跌歸零並讓 K 線多出平盤 K 棒、法人買賣超把股數當金額、盤勢分析快取永不過期。
- 財報資料來源修正（舊 dataset 名稱已失效，回 422）。

**新功能**
- 財報分析（損益、獲利率、成長、估值、股利、評分、趨勢圖）＋ AI 財報建議。
- 股票推薦（技術＋籌碼＋營收成長，4 種風格，可選「產業代表股」或「全市場成交值前 60」）。
- 產業研究（12 個產業排行、成分股評分、AI 產業報告）。
- K 線手動畫線（趨勢線、射線、水平線、垂直線、斐波那契、矩形；拖曳、磁吸、復原；AI 支撐壓力線可編輯）。
- 資料來源健康檢查端點：`/api/v1/research/health`。

**資料庫（Supabase → Neon）**
- 發現**原有建表 SQL 與程式碼欄位完全對不上**，且**前後端 API 約定多處不一致**（模擬交易、警報、投資組合從未真正串通）。已全面對齊，並用真實 Neon 資料庫跑 29 項整合測試，全數通過。
- 後端啟動時自動建表；沒設資料庫時行情類功能照常，資料庫功能回清楚的 503。

**可靠性**
- FinMind 額度用完時快速降級（不再卡住整個掃描），推薦頁會提示「僅含技術面」。
- 狀態橫幅改用輕量 `/health` 並放寬逾時，免費方案休眠時不再誤報。

## 3. 你要做的事（依序）

### ☐ A. 推送程式碼（約 1 分鐘）
Render 已設自動部署，推送後會自動重新建置。

```bash
git push origin main
```
**完成標準**：Render Logs 出現 `Database schema ensured`（若是 `資料庫初始化失敗`，代表 `DATABASE_URL` 有問題）。

### ☐ B. Render 環境變數（約 3 分鐘）
Render → `stock-backend` → Environment：

| 變數 | 必要性 | 說明 |
|---|---|---|
| `DATABASE_URL` | 必要 | **已由連接器設定好**，不必再動 |
| `FINMIND_API_KEY` | **強烈建議** | 到 finmindtrade.com 免費註冊取得。沒有的話額度很小，財報/籌碼/推薦會頻繁降級（日誌可見 `FinMind 額度/頻率限制`） |
| `GEMINI_API_KEY` | 選填 | 不填則使用者在網站「設定」頁輸入自己的 Key |
| `GEMINI_MODEL` | 已設定 | `gemini-2.5-flash` |

另外把 **Settings → Health Check Path** 設成 `/health`（建立工具不支援，需手動）。

### ☐ C. 前端接上後端（約 3 分鐘）
Vercel → 專案 `stock` → Settings → Environment Variables：

```
NEXT_PUBLIC_API_URL = https://stock-backend-lz9p.onrender.com
```
儲存後 **Redeploy**。（我沒有 Vercel 授權，這步只能由你做。）

### ☐ D. 安全：重設 Neon 資料庫密碼（約 2 分鐘）⚠️
連線字串（含密碼）在建立過程中**曾出現在這次對話的工具呼叫紀錄裡**。為保險起見：
1. Neon Console → 專案 `stock` → Roles → `neondb_owner` → **Reset password**。
2. 把新的連線字串更新到 Render 的 `DATABASE_URL`。

### ☐ E. 驗收清單（上線後逐項檢查）

| # | 檢查項目 | 預期結果 |
|---|---|---|
| 1 | 開啟 `<後端網址>/health` | `{"status":"ok"...}` |

| 5 | 個股 `6488`（上櫃） | 有報價與 K 線 |

### ☐ F. 選做
- **防休眠**：Render 免費方案閒置約 15 分鐘會休眠，喚醒要 30～60 秒。可用 UptimeRobot 等服務每 5 分鐘 ping 一次 `/health`。
- **清理舊檔**：`supabase/migrations/`、`init_db.sql`、`clear_db.py` 已與現行資料庫無關，可刪除以免誤導。Supabase 的暫停專案也可直接刪除。

## 4. 已知問題與限制（請知悉）

| 嚴重度 | 項目 | 說明 / 建議 |
|---|---|---|
| 🔴 高 | **沒有登入機制，所有訪客共用同一份資料** | 任何知道網址的人都能新增/刪除投資組合與模擬交易，且後端 CORS 為 `*`。若網站會公開，**必須**加驗證（見第 6 節 P0）。僅自己使用可暫時接受。 |
| 🟠 中 | **智慧警報不會自動觸發** | 目前只是「儲存條件」，沒有程式去評估「價格大於 2500」之類的文字條件並通知。 |
| 🟠 中 | AI 功能未用真實金鑰驗證 | 財報建議、推薦理由、產業報告、投資委員會只驗證了「沒金鑰時的錯誤處理」，AI 實際輸出品質未看過。 |
| 🟡 低 | 自選股存在瀏覽器 | 換裝置/清除資料就沒了；後端的 `watchlist` 資料表目前沒有被前端使用。 |
| 🟡 低 | 「AI 自動交易」開關只是前端假狀態 | 按鈕不會呼叫後端；排程任務也因需要資料庫而一直被停用。 |
| 🟡 低 | 推薦股票池是固定清單 | 「產業代表股」只涵蓋 `screener.py` 內的 `SECTORS`；「全市場熱門 60」較新但只看成交值。 |
| 🟡 低 | 免費方案的資料來源限流風險 | 雲端 IP 偶爾被 TWSE/Yahoo 限流；已有備援鏈，但請定期看健康檢查。 |

## 5. 還能引入的策略

> 現有回測引擎已含手續費（0.1425% × 折讓）與證交稅 0.3%，並內建 6 種策略：海龜、Supertrend、Dual Thrust、布林＋RSI、法人動能、均線交叉。下列為**尚未有**、且資料來源 FinMind 已提供的項目。

| 優先 | 策略 | 做法 | 資料來源 | 難度 |
|---|---|---|---|---|
| ★★★ | **月營收動能**（台股特色） | 營收 YoY 連續 3 個月 > 20% 且創 12 個月新高；公布日（每月 10 號前）後進場 | `TaiwanStockMonthRevenue`（已接） | 低 |
| ★★★ | **風控與部位試算** | 固定風險 1%：`股數 = 本金×1% ÷ (進場價−停損價)`；組合最大回撤熔斷；單一標的/產業上限 | 現有報價與 ATR | 低 |
| ★★★ | **相對強弱（RS）與產業輪動** | 個股/產業 20、60 日報酬對加權指數的超額，取前 20% 且站上月線 | 已有產業排行資料 | 低 |
| ★★☆ | **多因子排名** | 動能（12−1 月）＋品質（ROE、毛利率）＋價值（本益比百分位）等權排名，季度再平衡並回測 | 財報與 PER（已接） | 中 |
| ★★☆ | **大戶持股集中度** | 千張以上大戶持股比連續上升 + 價格橫盤 | `TaiwanStockHoldingSharesPer` | 中 |
| ★★☆ | **融資融券 / 券資比** | 融資大減 + 價格止跌（籌碼沉澱）、券資比過高（軋空） | `TaiwanStockMarginPurchaseShortSale` | 低 |
| ★★☆ | **高殖利率 ＋ 填息** | 殖利率排名 + 除息前布局、統計歷史填息天數 | `TaiwanStockDividend`、`TaiwanStockPER`（已接） | 中 |
| ★☆☆ | **均值回歸（ETF）** | 0050、0056 的 RSI(2) < 10 買、> 70 賣 | 日線（已有） | 低 |
| ★☆☆ | **事件日曆** | 除權息日、財報公布日提醒 | `TaiwanStockDividend`、財報日期 | 低 |

**回測可信度的補強**（比新增策略更值得先做）：
- 加入 **樣本外檢驗（walk-forward）**，避免過度擬合；
- 與 **0050 買進持有**同圖比較（目前有基準報酬，可再加夏普與回撤比較）；
- 納入下市/停牌標的，降低**倖存者偏差**；
- 滑價參數需確認是否真的有套用到成交價。

## 6. 路線圖（建議順序）

| 階段 | 項目 | 目的 |
|---|---|---|
| **P0 上線前** | 第 3 節 A～E 全部完成 | 網站可用 |
| **P0 若公開** | **加驗證**：最簡單是 Neon Auth 或在後端加一組共用的存取密鑰；至少把 CORS 限縮到你的 Vercel 網域 | 避免任何人改你的資料 |
| **P1** | 警報評估引擎：排程每幾分鐘評估「價格/成交量」條件，觸發後寫入 `message` 並通知（Email 或 LINE Notify） | 讓「智慧警報」名副其實 |
| **P1** | 申請 FinMind Key 並重新驗證推薦、財報在真實額度下的表現 | 資料完整度 |
| **P2** | 第 5 節 ★★★ 的三項策略 + 回測可信度補強 | 提升決策品質 |
| **P2** | 每日收盤後自動產生「AI 日報」（盤勢＋推薦＋自選股變化）寄到信箱 | 省去每天手動查看 |
| **P3** | 自選股、畫線同步到資料庫（需先有登入） | 跨裝置使用 |
| **P3** | 付費升級評估：Render 付費方案消除休眠；Neon 免費方案已足夠 | 穩定度 |

## 7. 可引入的 Claude Code skill / 工具

以下是你的環境中**已經可用**、且適合這個專案的項目：

| 名稱 | 用途 | 何時使用 |

| `security-review` | 檢查目前變更的安全問題 | 加驗證、公開網站之前，**P0 必做** |
| `engineering:code-review` / `/code-review` | 審查 diff 的正確性 | 每次大改動合併前（這次有大量新增程式碼，建議跑一次） |
| `engineering:testing-strategy` | 規劃測試覆蓋 | 目前只有資料層單元測試與手動整合測試，可補成可重複執行的自動化測試（含 CI） |

| `engineering:incident-response` | 事故排查流程 | 線上資料異常或後端掛掉時 |
