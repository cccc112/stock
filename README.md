# 台美股 AI 戰情室 (AI Stock Monitor & Simulator)

## 一、 專案概述

- **專案名稱：** 台美股 AI 戰情室 (AI Stock Monitor & Simulator)
- **目標受眾：** 需要同時跨足台美股，期望透過量化數據（籌碼、價量）與 AI 輔助來優化交易決策的投資人。
- **核心價值：** 整合主流券商的基礎行情報價，並加入「價量異常警報」、「動態支撐壓力運算」與「AI 投資模擬覆盤」等進階量化功能。

### 核心功能模組：
- 台美股即時報價與技術分析 (K線、五檔)
- 雙幣別庫存與帳務損益管理
- 智慧條件單與自動警報系統
- 價量異常掃描（高檔大量賣壓 / 低檔爆量承接）
- 動態支撐壓力網（VAP 籌碼密集區運算）
- AI 投資模擬與覆盤日記（Gemini API 驅動）

## 二、 商業模式與 AI (Gemini) 整合策略

為了在「開放給多用戶使用」與「控制 API 成本」之間取得平衡，系統採用混合式的架構：

1. **全域共用層 (Global Cache) - 系統負擔：**
   針對市場共同資訊（如：大盤解析、每日新聞總結），系統每小時呼叫一次 Gemini API，並將結果快取在資料庫中供所有用戶讀取，有效壓低固定成本。

2. **會員配額制 (Quota System) - 體驗與訂閱：**
   為降低新用戶門檻，系統為免費用戶提供每日少量的專屬 AI 呼叫額度（例如：每日 2 次自選股 AI 診斷）。進階用戶可透過付費訂閱提高額度。

3. **自帶金鑰模式 (BYOK - Bring Your Own Key) - 硬核玩家：**
   針對需要高頻率使用 AI 模擬交易的重度使用者，系統後台開放綁定個人 Google AI Studio API Key。這類用戶的運算成本由其個人帳號負擔，系統僅提供運算平台與演算法環境。

## 三、 系統技術堆疊與架構

- **前端 (Frontend):** React.js 或 Next.js (負責高效能圖表渲染與 WebSocket 串接)
- **後端核心 (Backend):** Node.js (Express) 或 Python (FastAPI)
- **量化與演算法引擎:** Python (Pandas, NumPy) (專責運算 VAP、均線、價量模型)
- **資料庫 (Database):**
  - PostgreSQL (儲存用戶資料、庫存、交易日誌)
  - Redis (處理即時報價快取與 API 頻率限制 Rate Limiting)
- **自動化排程 (Workflow):** n8n 或 Apache Airflow (負責定期觸發價量掃描與推播)

## 四、 開發階段與時程規劃

本計畫分為四個主要階段：

### 階段一：基礎建設與行情庫存 (M1 - M2)
- **目標：** 打造媲美券商 APP 的基礎骨架。
- **關鍵產出：**
  - 完成使用者註冊登入與權限管理。
  - 介接台美股行情報價 API (如 Yahoo Finance, 證交所 OpenAPI)。
  - 完成「自選股清單」與「互動式 K 線圖表」。
  - 完成「庫存管理」與損益試算模組。

### 階段二：量化運算與警報引擎 (M3)
- **目標：** 實作進階的價量模型與支撐壓力網。
- **關鍵產出：**
  - 開發 Python 模組：價格區間籌碼密集區 (VAP) 演算法。
  - 開發 Python 模組：高檔/低檔爆量判定邏輯。
  - 實作背景排程系統，當個股觸發條件或跌破支撐時，發送推播通知。

### 階段三：AI 深度整合與模擬系統 (M4)
- **目標：** 導入 Gemini API，賦予系統思考能力。
- **關鍵產出：**
  - 實作「全域共用層」的新聞與大盤 AI 總結。
  - 開發「AI 投資模擬」介面，讓用戶建立虛擬投資組合。
  - 撰寫 Prompt Engineering，讓 Gemini 能根據用戶的虛擬交易紀錄，產出針對性的「交易覆盤與優化報告」。

### 階段四：多用戶商用化準備 (M5)
- **目標：** 系統優化與計費機制上線。
- **關鍵產出：**
  - 實作 API 配額管理系統與 BYOK (自帶金鑰) 綁定功能。
  - 效能優化 (Redis 快取微調、資料庫索引優化)。
  - 部署至雲端環境 (AWS/GCP) 並進行壓力測試。

## 五、 風險評估與應對策略

- **金融合規風險：** 系統對外開放時，須在介面與 AI 報告中明確標示「免責聲明」，強調內容僅供模擬與學術討論，非實質投資建議。
- **即時報價授權成本：** 初期可先使用延遲報價或免費開源 API，待驗證商業模式且有營收後，再購買合法商用即時報價源。
- **AI Token 濫用 (Prompt Injection)：** 針對開放給用戶輸入備註讓 AI 讀取的功能，必須在後端實作嚴格的內容過濾，防止用戶下達惡意指令耗費系統 Token。
